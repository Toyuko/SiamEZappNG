# Production ops checklist (cannot be finished in app code alone)

Complete these before submitting store builds. App-side launch blockers from the
production-readiness passes are addressed in code; the items below need Expo
account / backend / device / store access.

## P0 — Security (do first)

1. **Rotate or disable** the production demo account previously used in the public repo (`freelancer@example.com`). Assume the password is compromised via git history.
2. Confirm no other seed/demo accounts accept known passwords against production.
3. Prefer OAuth **authorization code** exchange only; do not return JWT access tokens in redirect query strings.
4. Confirm website env for mobile sync:
   - `API_JWT_SECRET` (or `NEXTAUTH_SECRET` fallback) set on Vercel production
   - Social providers configured if store builds show Google/LINE/Facebook buttons
   - `APPLE_TEAM_ID` + `ANDROID_APP_SHA256_CERT_FINGERPRINTS` for Universal / App Links
5. App production `EXPO_PUBLIC_API_URL` / `EXPO_PUBLIC_WEB_BASE_URL` must be `https://siam-ez.com` (not the Vercel alias).

## Release tooling

1. Log in to Expo: `npx eas-cli login`
2. Create/link the project: `npx eas-cli init` (writes `extra.eas.projectId` into `app.json`)
3. Native projects are **gitignored** and generated by EAS / `expo prebuild` from `app.json`.
   Local validation already passes `npx expo prebuild --clean` with:
   - Android `com.siamez.app`, `allowBackup=false`, `SYSTEM_ALERT_WINDOW` removed
   - iOS `com.siamez.app`, when-in-use location only, PrivacyInfo present
4. Production builds:
   ```bash
   npx eas build --platform android --profile production
   npx eas build --platform ios --profile production
   ```

## Launch path (booking + payment)

- The app uses the **standard website booking**: `POST /api/bookings` with the
  service slug + `formData` / `documentIds` / guest contact fields.
- Live probe: catalog service slugs return **HTTP 201** with `caseId`,
  `caseNumber`, and (for guests) `guestCheckoutToken`.
- **Correct checkout URL** (matches `SiamEZwebNG` `BookingWizard` /
  `WizardEngine`):
  ```
  {webBaseUrl}/checkout/{caseId}?token={guestCheckoutToken}
  ```
  Putting the token in the path (`/checkout/{token}`) **404s** — the route param
  is a **case id**, not the token.
- Verified live: `/checkout/{caseId}?token=…` returns **HTTP 200** with checkout UI.
- The app opens that URL in the system browser. **Opening checkout is not payment
  success** — confirmation comes from the website/backend payment flow only.
- Authenticated users do not receive a guest token; they must complete payment
  after signing in on the website (external browser has no app JWT cookie).
- WhatsApp fallback remains available on the success screen.

- [ ] Account A → logout → Account B: no prior cases/documents/drafts
- [ ] Guest booking creates a case and returns a case number + checkout token
- [ ] Guest “Continue to payment” opens a working checkout page (`caseId` + `token`)
- [ ] Guest completes (or cancels) payment and returns to the app without false “paid” state
- [ ] Authenticated booking creates a case bound to the signed-in user
- [ ] Guest document upload blocked with clear message
- [ ] Camera / photo library permission prompts show SiamEZ-specific copy
- [ ] OAuth login (if enabled) lands without token in the URL bar
- [ ] Push: register while logged in; after logout, token cleared server-side
- [ ] Offline banner appears with airplane mode; booking fails with friendly copy
- [ ] Privacy policy + Terms links open from Profile
- [ ] Delete account prompts contact support (App Store account-deletion requirement)
